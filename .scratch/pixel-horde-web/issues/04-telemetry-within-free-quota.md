# Research: เก็บสถิติสำหรับ Admin v1 ให้อยู่ในโควตาฟรี

Type: research
Status: resolved
Blocked by: -

## Question

จะเก็บสถิติที่ Admin v1 ต้องใช้อย่างไรให้ไม่เกินโควตาฟรี? สถิติที่ต้องมี: คนเล่นต่อวัน/จำนวน Run/เวลาเล่น, ตายที่ Stage ไหน, Skill ที่เลือกและพาไปได้ไกล, retention D1/D7, error และ FPS, เทียบผลระหว่างเวอร์ชันของ Balance Config

ต้องได้คำตอบเรื่อง:
- ถ้าส่ง event หนึ่งครั้งต่อ Run (สรุปตอนจบ) กับส่งทีละ event ปริมาณข้อมูลต่างกันแค่ไหน ประมาณที่ 100 / 1,000 / 10,000 Run ต่อวัน
- การรวมเป็นชุดก่อนส่ง (batching) และการสุ่มเก็บบางส่วน (sampling)
- เก็บในตารางของเราเอง เทียบกับใช้บริการฟรีอย่าง PostHog, GameAnalytics, Cloudflare Web Analytics แบบไหนดีกว่า
- error/FPS ส่งไป Sentry (แพ็กฟรี) หรือเก็บเอง
- คำนวณ retention จากข้อมูลดิบด้วยวิธีไหน

## Answer

แนะนำให้**เก็บในตารางของเราเองบน backend ที่เลือก และส่งสรุปครั้งเดียวต่อ Run** (~0.8 KB แนบไปพร้อมคำขอส่งคะแนนได้) ที่ 10,000 Run/วัน ≈ 14k event หรือ ~10 MB ต่อวัน อยู่ในโควตาฟรีของทุกตัวเลือก (ยกเว้น Appwrite ที่ยืนยันโควตาไม่ได้) ต้องสรุปรวมทุกคืนและลบข้อมูลดิบเก่า (ที่ 10k Run/วัน เก็บดิบได้ ~14 วัน) ส่วนการส่งทีละ event (~60 ต่อ Run) เกินโควตาตั้งแต่ 1,000 Run/วัน

- ส่งผ่าน outbox ใน localStorage + `sendBeacon` ตอนแท็บถูกซ่อน, เก็บสรุปครบ 100% แต่เก็บรายละเอียดทีละจังหวะเฉพาะผู้เล่น 5%, ส่ง FPS เป็น histogram อยู่ในสรุปของ Run
- error เก็บเองในตารางที่รวมซ้ำตาม fingerprint (Sentry แพ็กฟรีใช้เสริมช่วงพัฒนาได้แต่ไม่จำเป็น)
- retention D1/D7 คำนวณจากตาราง `player_days` ตัดวันตามเวลาไทย แยกตามเวอร์ชัน Balance Config ได้ (มี SQL ทั้ง Postgres และ D1 ในไฟล์)
- PDPA: เก็บข้อมูลให้น้อย ไม่เก็บ IP มีปุ่มปิดการส่งสถิติ และระวังเรื่องส่งข้อมูลออกนอกประเทศ
- บริการภายนอก: PostHog เป็นแผนสำรองถ้าไม่อยากทำกราฟเอง / ไม่แนะนำ GameAnalytics (ข้อมูลดิบต้องเสียเงิน, ตัวแปรแยกกลุ่มได้แค่ 20 ค่า) และ GA4 (ความเป็นส่วนตัว) / Cloudflare Web Analytics ใช้ดูยอดเข้าหน้าเว็บได้อย่างเดียว
