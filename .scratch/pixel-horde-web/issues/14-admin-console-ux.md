# Prototype: หน้าจอและการใช้งาน Admin Console

Type: prototype
Status: resolved
Blocked by: 13

## Question

Admin Console v1 ควรมีหน้าจออะไรบ้าง และใช้งานยังไง? ทำ prototype หยาบๆ ให้ผู้ใช้ลองกดดู ครอบคลุม: แก้ Balance Config (ตัวคูณ, ช่วงค่า, เทียบกับเวอร์ชันก่อน, publish, rollback, ปุ่มทดสอบสดในเครื่อง), feature flags และโหมดปิดปรับปรุง, ตั้งอีเวนต์ตามเวลาและด่านท้าทายประจำวัน, dashboard สถิติ, ดูแล leaderboard และ Season, แจกเหรียญ/รีเซ็ตบัญชี, ประกาศ และ audit log

เพิ่มจาก #15: หน้าจอ Leaderboard ใน Admin ต้องมีการตรวจอันดับต้นๆ ของ co-op ด้วยตาก่อนแจกรางวัลจบ Season และหน้าเปิด Season ใหม่ต้องแสดงรายชื่อผู้ได้รางวัลให้ยืนยัน

## Answer

ตัดสินใจ 2026-09-24 จาก prototype 3 แบบ ผู้ใช้เลือกผสม: **โครงเมนูข้างแบบ A + หน้าแรกแบบ B (ห้องควบคุม) + หน้าค่าสมดุลแบบ C (ห้องจูน 3 ช่อง)**

Prototype (ทิ้งได้ เก็บเป็นหลักฐาน): branch `prototype/admin-console` ไฟล์ `apps/admin/prototype/admin-console-PROTOTYPE.html` (`?variant=A|B|C`)

**โครงหน้าจอ Admin Console v1** (เมนูข้างซ้าย ใช้บนคอมเป็นหลัก บนมือถือเมนูกลายเป็นแถบเลื่อนด้านบน):
1. **หน้าแรก: ห้องควบคุม** แถบตัวเลขสำคัญ (คนเล่นวันนี้, จำนวนรอบ, เวลาเล่นเฉลี่ย, D1/D7, error, FPS) + รายการ **"ต้องดู"** ที่ระบบคัดให้ แต่ละรายการมีปุ่มแก้ทันที (เปิดตัวแก้ค่าของห้องจูนเป็นแผงข้าง) + สวิตช์ด่วน + อีเวนต์ที่กำลังจะเกิดและด่านประจำวัน + ประกาศหน้าแรก + บันทึกล่าสุด
   - กฎที่ขึ้นรายการ "ต้องดู": Chapter ที่ผู้เล่นหลุดผิดปกติ (เทียบเวอร์ชันก่อน), คะแนนน่าสงสัย (เช่น เร็วกว่าเวลาขั้นต่ำ), error ใหม่หรือพุ่ง, สกิลที่พาไปได้ไกลเกิน/น้อยเกินเป้า, Gold ของผู้เล่นสูงผิดปกติ, โควตาฟรีใกล้เต็ม (พื้นที่/egress ของ Supabase, request ของ Durable Object), อันดับ co-op ที่รอตรวจก่อนจบ Season
2. **ค่าสมดุล: ห้องจูน 3 ช่อง** ซ้าย: รายการค่าทั้งหมดตาม schema แบ่งกลุ่ม + ค้นหา (ค่าที่แก้แล้วเป็นตัวสีส้ม) · กลาง: ค่าที่เลือกเป็นตัวเลขใหญ่ + แถบเลื่อน/ช่องพิมพ์ + ตรวจช่วงค่าทันที + คืนค่าเดิม + กราฟผลกระทบ (เทียบเวอร์ชัน) + ค่านี้ในแต่ละเวอร์ชัน · ขวา: รายการ "รอ publish" (ค่าเดิม → ค่าใหม่) + โน้ต + **ทดสอบสดในเครื่อง** + Publish + รายการเวอร์ชันพร้อมย้อนกลับ
3. **สวิตช์และอีเวนต์**: feature flags (ป้าย "ทันที"), โหมดปิดปรับปรุง, เวอร์ชันเกมขั้นต่ำ (บังคับรีเฟรช), อีเวนต์ตามเวลา (เพิ่ม/แก้/ลบ), ด่านประจำวัน (ดูที่สร้างล่วงหน้า แก้ฮีโร่/อาวุธได้)
4. **สถิติ**: ตัวเลขสำคัญ, ผู้เล่นที่รอดต่อ Chapter (เทียบเวอร์ชัน), สกิลที่เลือก/พาไปได้ไกล, retention, error ที่เจอบ่อย, FPS
5. **Leaderboard**: แท็บตามตาราง (Season solo/co-op, Endless, ประจำวัน), ป้ายสถานะ (ยืนยันแล้ว/รอตรวจ/น่าสงสัย), ซ่อนคะแนน/แบน, **เปิด Season ใหม่พร้อมหน้ายืนยันรายชื่อผู้ได้รางวัล** (co-op ต้องติ๊กตรวจอันดับต้นๆ ก่อน)
6. **ผู้เล่น**: ค้นหา, Gold, ผูก Google แล้วหรือยัง, ฉายา, แจกเหรียญชดเชย, รีเซ็ตบัญชี, แบน/ปลดแบน
7. **ประกาศหน้าแรก** (ไทย/อังกฤษ, เวลาเริ่ม-จบ)
8. **บันทึกการแก้ไข** (อ่านอย่างเดียว บันทึกโดยฐานข้อมูล)

สิ่งที่ยืนยันจากการกดลองใน prototype: การตรวจช่วงค่า (พิมพ์ 9 ในช่องที่รับ 0.3–3 → เตือน), การ publish/ย้อนกลับเป็นเวอร์ชันใหม่เสมอ (ไม่แก้ทับประวัติ), ทุกการกระทำเข้าบันทึก
